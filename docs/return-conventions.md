# Проверка доходностей и новый редактор портфеля

Проверено 2026-10-06 на существующей базе, без ingestion и изменения наблюдений.
Воспроизводимые результаты: [return-conventions-check.json](return-conventions-check.json).

## Почему доходности различались

На прежнем графике «Доходность» означала `mean(monthly returns) × 12` —
арифметическую ожидаемую доходность для оптимизации Markowitz. CAGR — другой
показатель: `exp(mean(log(1 + monthly returns)) × 12) − 1`. Он учитывает
накопление капитала. Одинаковые месячные наблюдения дают разные значения этих
двух показателей; это не ошибка загруженных месячных returns.

| Актив | Месяцы доходностей | Количество | Арифметическая, годовая | CAGR | Историческая волатильность, ddof=0 | Sample, ddof=1 |
|---|---|---:|---:|---:|---:|---:|
| VTI | 1793-01—2026-08 | 2804 | 9.228036% | 8.450307% | 14.782548% | 14.785185% |
| IJS | 1927-01—2026-08 | 1196 | 14.265510% | 12.840182% | 20.564916% | 20.573519% |
| IJS | 1927-01—2026-09 | 1197 | 14.195036% | 12.760738% | 20.568361% | 20.576958% |

Таким образом, пара IJS **14.20% / 12.76%** воспроизводится на истории до
**сентября**, который уже присутствует в базе IJS. До августа значения другие.
При выборе нескольких активов используется общий период; если один ряд
заканчивается августом, сентябрь IJS в этот расчёт не попадёт.

Для VTI большая разница объясняется сравнением арифметической доходности с CAGR.
Остаток между рассчитанными **8.4503%** и указанными пользователем **8.44%**
в интерактивном LazyPortfolioETF backtester пока не воспроизведён. В сохранённой
исходной странице VTI опубликован `returnAnn=8.4503`, `stdDev=14.7825`.
Это сверка с сохранённой страницей инструмента, а не доказательство идентичности
параметров интерактивного backtester. Причина остатка не установлена;
наблюдения и формулы не подгонялись под 8.44%.

Декабрь перед первым январским return — точка первоначального капитала:
месячное изменение за январь применяется к капиталу на конец декабря. Поэтому
1792-12 как начало инвестирования и 1793-01 как первый месяц доходностей
сами по себе не означают отсутствующий return.

Историческая волатильность теперь возвращается отдельно:
`std(monthly portfolio returns, ddof=0) × sqrt(12)`. Для Sample Covariance
оценка риска остаётся с `ddof=1`; остальные методы используют свои оценки
ковариации. Sharpe сохраняет прежнее определение: арифметическая ожидаемая
доходность минус заданная постоянная годовая безрисковая ставка, делённые на
оценку волатильности.

## Как пользоваться

Откройте [локальный Portfolio Lab](http://127.0.0.1:5173) и выберите **Live**.
Команды запуска приведены в [ui/README.md](../ui/README.md).

1. Верхний блок начинается с пяти строк. Нажмите поле тикера: доступны поиск,
   исходные категории, названия и сроки истории. «Добавить актив» добавляет
   строку, максимум 15. Пустые строки не участвуют в расчёте.
2. Здесь же задайте индивидуальные Min/Max и номера пользовательских групп 1–5.
   В левом блоке появляются только использованные группы. Они задают явные
   ограничения, одинаковые для Frontier, CV и bootstrap.
3. Оставьте аллокации пустыми/нулевыми либо укажите ровно 100% в сумме.
   Например, VTI 100%, остальные выбранные инструменты 0%.
4. Нажмите **Рассчитать** на Frontier. «Ваш портфель» появится в таблице и на
   графике с оценками Python backend. Нарушение ограничений помечается как
   reference; заданные пользователем веса не исправляются автоматически.
5. График показывает исторические CAGR/волатильность. Историческое представление
   показывает характеристики тех же оптимизированных весов, а не новую
   оптимизацию по CAGR и не точную классическую границу в этих координатах.

## Дополнения API и снимков

Все четыре запроса допускают новые поля (прежние клиенты совместимы):

```json
{
  "instrument_ids": [1, 175, 243],
  "asset_groups": {"1": 1, "175": 3, "243": 5},
  "group_constraints": {
    "Group 1": {"min": 0, "max": 0.8},
    "Group 3": {"min": 0, "max": 1},
    "Group 5": {"min": 0, "max": 1}
  },
  "user_weights": {"1": 1, "175": 0, "243": 0}
}
```

Ключи — ID инструментов, не тикеры. `user_weights` — доли, не проценты;
`null`, пустой словарь или сумма ноль отключают пользовательский портфель.
Иная ненулевая сумма вызывает 422. `asset_groups` разрешает только выбранные
ID и целые номера 1–5. Исходные категории сохранены независимо от этих групп.

Frontier возвращает `user_portfolio` (или `null`), с `weights`, `metrics`,
`feasible`, `label` и диагностикой нарушения ограничений. Все описания
портфелей включают `metrics.historical_volatility`; `volatility` по-прежнему
обозначает риск из выбранной ковариации. `allocation_groups` раскрывает
использованные отображения групп. Полные схемы: [OpenAPI](analytics-demo/openapi.json).

Версия движка — **1.2.0**. Новые поля входят в полный сохранённый запрос,
повторение и сравнение JSON. Старые снимки открываются; отсутствующая
историческая волатильность заменяется сохранённой оценкой риска, без расчётов JS.

`asset_portfolios` содержит серверные показатели каждого актива за общий период
анализа при весе 100%. В UI они показаны розовыми ромбами с тикерами на Frontier,
Compare и Resampled Frontier. Исходные ограничения не изменяют эти справочные
точки. Старые снимки без `asset_portfolios` открываются; для появления точек
активов нужно повторить расчёт в Live.

## Воспроизведение диагностики

```powershell
.\.venv\Scripts\python.exe -m scripts.diagnose_return_conventions
```

Скрипт читает валидированные USD-ряды, проверяет непрерывность месяцев,
записывает контрольные суммы и подтверждает неизменность байтов базы.
