# QCross Portfolio Lab — локальный UI

React + TypeScript + Plotly. Расчёты выполняет существующий Python backend;
frontend отображает ответы и сравнивает снимки, не оценивает ковариацию и не оптимизирует веса.

## Быстрый запуск Demo — без базы и FastAPI

Требуется Node.js >= 22.12 (проверено на 24.19).
Из корня репозитория в PowerShell:

```powershell
cd ui
npm ci
npm run dev
```

Откройте **http://127.0.0.1:5173**. `predev` копирует существующие
`docs/analytics-demo/*.json` в игнорируемую папку `public/demo/`.
Python и база для этого не нужны. Все шрифты и библиотеки локальные.
Demo содержит реальные сохранённые USD-истории VTI / TLT / GLD, период
1990-01—2026-08, 440 месяцев. Это исторические реконструкции; предупреждения
источников видны в интерфейсе. Demo не генерирует фиктивные результаты:
настройки сценария заблокированы, можно выбирать четыре сохранённых метода.
CV и Bootstrap сохранены только для Sample Covariance.

## Live — существующая база

Первый терминал, из корня репозитория:

```powershell
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Второй терминал:

```powershell
cd ui
npm run dev
```

Нажмите **Live**. Vite проксирует `/api` в FastAPI на порту 8000.
Для другого адреса задайте `$env:QCROSS_API_URL='http://127.0.0.1:8001'`
перед запуском Vite. Браузерный код остаётся same-origin, настройка CORS не нужна.
`VITE_API_BASE_URL` — необязательный адрес API для будущей интеграции;
для отдельного origin соответствующий CORS на сервере потребуется настроить отдельно.
Имеющуюся базу не надо пересоздавать, запускать ingestion или скачивать историю.

1. Найдите и выберите 2–15 инструментов из валидированного USD-каталога.
   Общие исходные даты отображаются сразу. Backend автоматически проверяет
   эффективную выборку при смене активов/дат; кнопку проверки можно нажать отдельно.
2. Укажите даты, covariance method, min/max активов и групп, постоянную годовую
   безрисковую ставку (3% по умолчанию). Ограничения задаются в процентах;
   API получает доли. Членство групп поступает из базы, включая пересечения.
3. На **Frontier** нажмите **Рассчитать**. Наведение показывает показатели и веса;
   клик по точке или портфелю открывает распределение. Equal Weight явно отмечен
   как unconstrained reference, если нарушает ограничения.
4. На **Cross-validation** выберите цель заранее, K=2–10 и запустите расчёт.
   Для K=5 нужно минимум 150 общих месяцев. Таблица отделяет validation-метрики
   фолдов от full-sample оценки CV Ensemble.
5. На **Bootstrap** задайте seed, L=3–24, повторения (по умолчанию 1000), нажмите
   **Рассчитать**. Рассчитываются GMV и Max Sharpe. Видны интервалы, распределения,
   частоты границ, allocation distance и все ошибки итераций.
6. Для **Resampled Frontier** задайте, например, 250 повторений и 51 точку и
   нажмите отдельную кнопку. Лимиты API: <=500 повторений, <=30 000 оптимизаций.
   Число повторений не уменьшается автоматически. Target-return режим bootstrap
   не поддерживает: выберите GMV или Max Sharpe.
7. На **Compare** кнопка **Сравнить 4 метода** последовательно отправляет четыре
   Frontier-запроса с одинаковой выборкой и ограничениями. Для stochastic-расчётов
   используйте одинаковый seed/L/число повторений при смене метода; backend создаёт
   одинаковые bootstrap-индексы, fingerprint остаётся в JSON.

Результаты, относящиеся к прежним настройкам, явно помечены. Совмещаются только
совместимые запросы с одинаковым SHA-256 матрицы. Для отсутствующего результата
показано пустое состояние. Ошибка API никогда не подменяется успешным Demo.
Если успешно <95% bootstrap-итераций, статус `incomplete` виден отдельно.

## Задания и ошибки

Используются четыре POST `/api/v1/analytics/{frontier,cross-validation,bootstrap,resampled-frontier}`,
GET `/jobs/{id}` и `/jobs/{id}/result`. Дополнительные read-only endpoints:
GET `/api/v1/analytics/catalog`, POST `/api/v1/analytics/data-preview`.
Прикладные ограничения и существующие bounded процессы backend сохраняются:
два одновременных задания, timeout 300 секунд (настраивается в backend),
429 при заполнении ёмкости, хранение результата один час в памяти.
В текущем backend учитываются также сохранённые результаты (максимум 32).
После нескольких полных прогонов дождитесь истечения retention или
перезапустите локальный FastAPI; браузер не удаляет результаты других заданий.
UI опрашивает статус каждые 350 ms, timeout отдельного HTTP-запроса — 15 секунд.
`Отменить ожидание` прекращает ожидание в браузере, но не отменяет процесс на сервере.
Новые background-потоки и распределённая инфраструктура не добавлены.

## JSON-снимки и воспроизводимость

**Сохранить JSON** экспортирует все видимые/сохранённые расчёты без округления.
**Загрузить JSON** проверяет структуру, открывает результаты без сервера и сохраняет
их как baseline. Ограничение файла: 80 MB, 32 расчёта. Используется схема
`qcross-portfolio-lab/v1`: время снимка, каталог инструментов, `calculations[]`.
Каждый элемент содержит `kind`, полный `request`, полный `result`, происхождение и дату.

`result.reproducibility` содержит:

- `engine`: семантическую версию 1.0.0, SHA-256 исходных Python-модулей и версии численных библиотек;
- `source_series`: instrument/series IDs, `series_version` и `series_sha256`, timestamp,
  источник, валюту, число наблюдений. Версия ряда — content hash полного сохранённого
  ряда; записи и metadata в базе не меняются;
- `returns_matrix_sha256`: SHA-256 canonical JSON `{assets,months}` + LF +
  row-major little-endian float64 bytes фактически выровненной матрицы;
- `api_request`, `random_seed`, `optimization_parameters`.

**Snapshot → Повторить снимок через Live** отправляет точные сохранённые запросы
последовательно. API явно сохраняет эффективные bootstrap objectives, чтобы
повторение default-запроса не меняло набор целей. Сравнение проверяет все численные
поля ответа, включая отдельные bootstrap-итерации:
`|new - saved| <= absTolerance + relTolerance * |saved|`.
По умолчанию abs=1e-7, rel=1e-6; допуски можно изменить перед повторением.
Время выполнения, timestamps и счётчики solver-итераций исключены.
Изменения движка/библиотек/рядов/матрицы выделены предупреждениями независимо
от совпадения чисел. Полные различия можно скачать отдельным JSON.
Хеш обеспечивает идентификацию данных, а не цифровую подпись доверенного источника.

## Проверки и сборка

```powershell
cd ui
npm test
npm run build
npm run format:check
npx playwright install chromium
npm run test:e2e
```

По умолчанию Live browser-тест пропущен; Demo проверяется с заблокированными API-запросами.
Для реальной интеграции запустите FastAPI с существующей базой в другом терминале:

```powershell
$env:QCROSS_LIVE_TEST='1'
npm run test:e2e
```

Live-тест реально запускает все четыре задания (1000 bootstrap и 250×51 resampled),
сравнивает четыре метода, экспортирует/загружает JSON, повторяет все семь расчётов
и проверяет допуски. Отдельные тесты с mock API проверяют ошибки и обнаружение различий.
Скриншоты desktop/mobile и времена Live-заданий: `docs/ui-verification/`.
Vitest тесты используют сохранённые расчёты как fixtures и mock HTTP для ошибок.
Backend pytest использует явно синтетические временные базы.

В корне для регрессии backend:

```powershell
.\.venv\Scripts\python.exe -m pytest
.\.venv\Scripts\python.exe -m ruff check .
```

Для обновления Demo по существующей базе (не требуется при обычном запуске):

```powershell
.\.venv\Scripts\python.exe -m scripts.analytics_demo
cd ui
npm run demo:sync
```

## Структура / будущий перенос

```text
ui/
  src/App.tsx                   # orchestration, режимы, snapshots
  src/components/Settings.tsx   # выбор активов, период, параметры, ограничения
  src/components/Results.tsx    # Frontier, CV, Bootstrap, Compare
  src/components/Plot.tsx       # lazy browser-only Plotly adapter
  src/components/PortfolioTable.tsx
  src/lib/{api,snapshot,validation,display}.ts
  src/types.ts                  # shared API contracts
  src/styles.css
  src/test/                     # Vitest / Testing Library
  e2e/lab.spec.ts               # Chromium / реальный API и ошибки
  scripts/sync-demo.mjs
```

`lib/` и компоненты отделены от Vite; Plotly загружается после mount.
Для Next.js нужны client component boundary и same-origin proxy/API URL,
но сам перенос и публичное развёртывание в этой задаче не выполняются.
